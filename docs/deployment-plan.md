## 2. Deployment Overview & Scope

### 2.1 Objectives

นำระบบบันทึกเวลาเข้า-ออกงานขึ้นใช้จริงบนเครื่องเซิร์ฟเวอร์ในออฟฟิศ **เป็นการติดตั้งครั้งแรก (greenfield)** ให้พนักงานลงทะเบียนและบันทึกเวลาผ่านเบราว์เซอร์มือถือบน Wi-Fi เดียวกัน โดยข้อมูลต้องไม่หายเมื่อเครื่องรีสตาร์ท และต้องกู้คืนได้เมื่อเครื่องเสีย

### 2.2 Scope of Changes

- **Components Affected:** Frontend (หน้า login/register/บันทึกเวลา/แดชบอร์ด) · Backend API (FastAPI) · Database (PostgreSQL ฐานข้อมูล `clockin` ใหม่ ตาราง `employees`, `attendance`) · ไฟล์รูป (`uploads/`)
- **User Impact:** ไม่มีผู้ใช้เดิมให้กระทบ (ระบบใหม่) · ช่วงติดตั้งแจ้งพนักงานว่าระบบยังใช้ไม่ได้ · **ทุกครั้งที่รีสตาร์ทเซิร์ฟเวอร์ ผู้ใช้ทุกคนต้องล็อกอินใหม่** (session อยู่ในหน่วยความจำ) แต่ข้อมูลไม่หาย
- **Data migration:** ไม่มี (ฐานข้อมูลเริ่มว่าง — ข้อมูลทดสอบถูกล้างด้วย `app.cli wipe-data` ก่อนขึ้นจริง)

### 2.3 Target Environment

| รายการ | ค่า | หมายเหตุ |
|---|---|---|
| เครื่อง | Windows 1 เครื่อง เปิดตลอด 24 ชม. (SA: i5 gen4 / RAM 8 GB) | เครื่องพัฒนาแรงกว่านี้มาก — ต้อง**ทดสอบซ้ำบนเครื่องจริง** (ดู 4.6) |
| โฟลเดอร์ติดตั้ง | `C:\clock-in-der` | **ห้ามใช้ path ของโฟลเดอร์พัฒนา** (มีเครื่องหมาย `'` และภาษาไทย → Task Scheduler/quoting พังง่าย) |

### 4.5 ขนาดข้อมูล (ต้องรู้ก่อนขึ้น)

## 5. Deployment Runbook (Step-by-Step)

### 5.0 ก่อนเริ่ม

- เลือกช่วง**นอกเวลางาน** แจ้งพนักงานล่วงหน้าว่าช่วงนั้นระบบใช้ไม่ได้
- เตรียมไว้: รหัส `postgres` (ผู้ถือ) · รหัสใหม่สำหรับ user `clockin` (ตั้งใหม่ ยาว ≥ 12 ตัว ตัวอักษร+ตัวเลข หลีกเลี่ยง `@ : / ? # %`) · สิทธิ์ Administrator บนเครื่องเซิร์ฟเวอร์
- เปิด PowerShell **แบบ Administrator** (จำเป็นสำหรับ firewall และ Task Scheduler)

## 6. Rollback & Contingency Plan

### 6.1 Rollback Criteria

ย้อนกลับเมื่อพบอย่างใดอย่างหนึ่งหลังติดตั้ง/อัปเดต:
- Smoke Test (7.1) ข้อใดข้อหนึ่งไม่ผ่าน และแก้ไม่ได้ภายใน **30 นาที**
- พนักงานบันทึกเวลาไม่สำเร็จเป็นวงกว้าง (เข้าหน้าไม่ได้ / ล็อกอินไม่ได้ / อัปโหลดรูปไม่ผ่าน มากกว่า 1 ใน 3 ของผู้ใช้)
- ข้อมูลเพี้ยนหรือหาย: เวลาเข้า-ออกผิด, ชั่วโมงสะสมไม่ตรง, รูปไม่ตรงคน, แถวหายหลังรีสตาร์ท
- เครื่องเซิร์ฟเวอร์ไม่เสถียร (RAM/ดิสก์เต็ม, ค้าง) จนระบบหยุดบ่อย

ผู้ตัดสิน: Deployment Lead

### 6.2 Rollback Steps

**(1) ย้อนโค้ด** — ใช้เมื่อรุ่นใหม่มีบั๊กแต่ฐานข้อมูลยังปกติ
1. `schtasks /End /TN "clock-in-der"` (หยุดแอป ยืนยันว่าพอร์ต 8000 ว่าง)
2. `git checkout <tag ก่อนหน้า>` (หรือคัดลอกโฟลเดอร์รุ่นเก่าที่เก็บไว้กลับ)
3. `.venv\Scripts\python.exe -m pip install -r requirements.txt`
4. `schtasks /Run /TN "clock-in-der"` แล้วทำ Smoke Test 7.1
> `init-db` ของรุ่นใหม่ที่ **เพิ่ม**คอลัมน์/ตารางไม่ทำให้รุ่นเก่าพัง (รุ่นเก่าไม่รู้จักก็ไม่ใช้) แต่ถ้ารุ่นใหม่**เปลี่ยน/ลบ**โครงสร้าง ต้องกู้ฐานข้อมูลตามข้อ (2) ด้วย

**(2) กู้ฐานข้อมูล** — ใช้เมื่อ schema/ข้อมูลเสียหาย ⚠️ **ข้อมูลที่บันทึกหลังเวลาของ backup จะหาย**
1. หยุดแอป (ข้อ 1.1)
2. เลือกชุดล่าสุดที่ดี: `Get-ChildItem C:\clock-in-der\backups | Sort-Object Name -Descending`
3. กู้ (รันที่โฟลเดอร์โปรเจกต์ ใส่รหัส `clockin` เมื่อถูกถาม หรือตั้ง `$env:PGPASSWORD` เฉพาะในหน้าต่างนั้น แล้วปิดหน้าต่างทิ้ง):
   ```powershell
   & "C:\Program Files\PostgreSQL\17\bin\pg_restore.exe" -h localhost -p 5433 -U clockin -d clockin --clean --if-exists --no-owner "C:\clock-in-der\backups\<ชุด>\clockin.dump"
   ```
4. กู้รูป (เพิ่มเติม ไม่ลบของเดิม): `robocopy "C:\clock-in-der\backups\<ชุด>\uploads" "C:\clock-in-der\uploads" /E`
5. เปิดแอป แล้ว Smoke Test 7.1 + ตรวจจำนวนแถวเทียบก่อนหน้า (ภาคผนวก A)

**(3) รีบูตแล้วแอปไม่ขึ้นเอง** — ดู `logs\server.log` (ท้ายไฟล์): "ต่อฐานข้อมูลไม่ได้" = service PostgreSQL ยังไม่ขึ้น/พอร์ตผิด · ใช้ `schtasks /Run /TN "clock-in-der"` เปิดมือได้ทันที

เวลากู้โดยประมาณ (ยังไม่ได้จับเวลาบนเครื่องจริง): **15–30 นาที** · ข้อมูลที่อาจหายสูงสุด = ช่วงตั้งแต่ backup ล่าสุด (ปกติ ≤ 24 ชม. ต่อการตั้งรายวัน — จึงต้อง backup ทันทีก่อนทุกการอัปเดต B2)

## 9. Known Limitations & Accepted Risks

ทุกข้อด้านล่างเป็นความเสี่ยงที่**รับรู้แล้ว** ไม่ใช่ข้อผิดพลาดที่ลืม — ผู้อนุมัติต้องรับทราบก่อนขึ้นจริง

| # | ข้อจำกัด / ความเสี่ยง | ผลกระทบ | แผน / ผู้รับผิดชอบ |
|---|---|---|---|
| 1 | ใช้ **HTTP** ไม่ใช่ HTTPS: PIN วิ่งไม่เข้ารหัสใน LAN, cookie ไม่มี `Secure` | คนในเครือข่ายเดียวกันที่ดักข้อมูลได้เห็น PIN ได้ | SA 7.5: ยอมรับใน v1 · ระยะต่อไป HTTPS (self-signed/mkcert) |
| 2 | **ใครอยู่ใน LAN ก็ลงทะเบียนได้** ไม่มีขั้นอนุมัติ และ**ทุกคนที่ล็อกอินเปิดแดชบอร์ดดูรูปทุกคนได้** (D9) | คนแปลกหน้า/พนักงานด้วยกันเห็นข้อมูลและรูปของทุกคน | จำกัดด้วย Wi-Fi ออฟฟิศรหัสผ่านแข็งแรง · ระยะต่อไป: แยกสิทธิ์ + อนุมัติ |
| 3 | กันโกงรูปไม่ได้: iOS/Desktop แนบรูปเก่าได้ (SA 7.1) · รู้ PIN ก็กดแทนกันได้ | เวลาเข้า-ออกอาจไม่ใช่ตัวจริง | รูปไว้ตรวจย้อนหลัง · ระยะต่อไป HTTPS → face-match |
| 4 | **ไม่ย่อรูป (NFR4)** | ดิสก์โตเร็ว (4.5) | ตัดสินใจก่อนขึ้นจริง |
| 5 | ยังไม่มีสคริปต์ลบรูปเกิน 1 ปี (D8) | เก็บรูปเกินที่แจ้งพนักงานไว้ | ทำก่อนครบ 1 ปีแรก |
| 6 | session + ตัวนับ PIN ผิดอยู่ในหน่วยความจำ | รีสตาร์ทแล้วทุกคนต้องล็อกอินใหม่ | ยอมรับ · อัปเดตนอกเวลา |
| 7 | เซิร์ฟเวอร์ตัวเดียว (single point of failure), ไม่มีระบบสำรองอัตโนมัติ | เครื่องเสีย = ใช้ไม่ได้จนกว่ากู้ (6.3) | แผนจดมือ + backup นอกเครื่อง |
| 8 | ไม่มีเครื่องมือ migration schema | อัปเดตที่เปลี่ยนโครงสร้างต้องเขียนสคริปต์ย้ายเอง | เพิ่ม Alembic ถ้าเริ่มเปลี่ยน schema บ่อย |
| 9 | log ไม่หมุนไฟล์ · ไม่มี `/health` · ไม่มีแจ้งเตือน | ปัญหาถูกพบช้า | ตรวจมือตาม 7.3 |
| 10 | ทดสอบความเร็วบนเครื่องจริงและกล้องบนมือถือจริงยังไม่ทำ | อาจพบปัญหาหน้างาน | blocking ใน 4.6 |
| 11 | รหัสผ่านบัญชี `clockin`/`postgres` อยู่ในมือคนติดตั้ง และใน `.env` ของเครื่อง | รั่ว = เข้าฐานข้อมูลได้ | จำกัดสิทธิ์ไฟล์ (A4) · ไม่ส่งทางแชท · เปลี่ยนรหัสเมื่อเปลี่ยนผู้ดูแล |
| 12 | ข้อมูลรูปใบหน้า = ข้อมูลส่วนบุคคล และ backup ก็มีรูปด้วย | ต้องดูแลตามกฎหมายคุ้มครองข้อมูลส่วนบุคคล | แจ้งวัตถุประสงค์/ระยะเก็บ (ข้อ 8) · จำกัดผู้เข้าถึง backup · ไม่ขึ้น cloud สาธารณะ |

## ภาคผนวก A — คำสั่งที่ใช้บ่อย (คัดลอกวางได้)

รันที่ `C:\clock-in-der` — คำสั่งที่ลงท้าย ✅ ผ่านการทดสอบจริงแล้ว

```powershell
# สถานะ
Get-Service postgresql-x64-17                                    # ต้อง Running

schtasks /Query /TN "clock-in-der" /V /FO LIST                   # งานเปิดแอป ⚠️
schtasks /Query /TN "clock-in-der backup" /V /FO LIST            # งาน backup ⚠️
Get-Content logs\server.log -Tail 30 -Encoding utf8              # log ล่าสุด

# เปิด/ปิดแอป ⚠️
schtasks /Run /TN "clock-in-der"
schtasks /End /TN "clock-in-der"

# ฐานข้อมูล ✅
.venv\Scripts\python.exe -X utf8 -m app.cli init-db
.venv\Scripts\python.exe -X utf8 -m app.cli reset-pin "ชื่อ-นามสกุล"

.venv\Scripts\python.exe -X utf8 -m app.cli wipe-data --confirm clockin     # ลบจริง ต้องพิมพ์ชื่อฐานข้อมูลให้ตรง (+ --photos ลบรูปด้วย)

# สำรอง ✅
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1

```
